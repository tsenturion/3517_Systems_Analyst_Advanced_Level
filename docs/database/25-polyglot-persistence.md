# Распределение данных между хранилищами HelpDesk

## Решение DB-002

Использовать специализированные хранилища
для отдельных категорий данных.

## Распределение ответственности

| Хранилище  | Назначение                            | Статус              |
| ---------- | ------------------------------------- | ------------------- |
| SQLite     | Рабочие данные API и Outbox           | Используется        |
| PostgreSQL | Реляционная модель предметной области | Учебная копия       |
| Redis      | Кеш результатов API                   | Реализован прототип |
| MongoDB    | Копии интеграционных событий          | Реализован перенос  |
| Prometheus | Технологические метрики               | Используется        |

## Правила работы с Redis

Время жизни кешированных данных: 60 секунд.

При отсутствии значения обращаться к API.

При недоступности Redis обращаться к API.

Кеш не является основным источником данных.

Инвалидация выполняется вручную в рамках упражнения.

## Правила работы с MongoDB

Каждый документ имеет идентификатор события.

Повторный перенос не создаёт дубликатов.

Исходные события остаются в Outbox.

Синхронизация выполняется запуском Python-скрипта.

MongoDB не участвует в доставке сообщений RabbitMQ.

## Ограничения

Автоматическая синхронизация пока не реализована.

Автоматическая инвалидация кеша пока не реализована.

Кеширование в действующий FastAPI пока не встроено.
