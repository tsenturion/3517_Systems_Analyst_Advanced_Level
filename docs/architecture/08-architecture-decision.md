# Архитектурное решение HelpDesk

## Решение ARCH-001

Статус: предварительно принято.

### Рассмотренные варианты

Монолитная архитектура.

Сервис-ориентированная архитектура SOA.

Микросервисная архитектура.

### Условия проекта

Небольшая команда разработки.

Ограниченное количество функциональных областей.

Единый жизненный цикл выпуска приложения.

Связанные данные пользователей и заявок.

Предполагаемая умеренная начальная нагрузка.

### Выбранный подход

Модульный монолит.

### Обоснование

Основная функциональность HelpDesk может быть
реализована внутри единого приложения.

Разделение на модули позволит разграничить
ответственность между частями системы.

Единое развёртывание упростит первоначальную
разработку и сопровождение.

### Последствия

Необходимо поддерживать внутренние границы модулей.

Изменения модулей выпускаются в составе приложения.

Внешние системы могут подключаться через
специально предусмотренные интерфейсы.

### Условия пересмотра

Появление независимых команд разработки.

Значительное увеличение масштаба системы.

Необходимость независимого масштабирования компонентов.
