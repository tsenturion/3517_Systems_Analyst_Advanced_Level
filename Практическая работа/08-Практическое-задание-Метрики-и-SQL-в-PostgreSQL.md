# Практическое задание «Метрики и SQL в PostgreSQL»

**Темы курса** — 5.1 «Зачем системному аналитику анализ данных. Анализ состояния систем по технологическим метрикам» и 5.2 «Базовые и продвинутые SQL-процедуры на примере PostgreSQL».

## Цель

Ответить на два вопроса о работе сервиса бронирования с помощью SQL. Определить, в какой час поступает больше всего заявок и сколько заявок ещё рассматривают на каждой площадке. По результатам сформулировать выводы, указав период и границы выборки.

## Задание

### Шаг 1. Загрузите учебные данные

Откройте редактор запросов, подключённый к учебной базе PostgreSQL. Например, в pgAdmin выберите учебную базу и откройте **Query Tool**. Скопируйте весь SQL-блок из раздела «Учебные данные» и запустите его кнопкой **Execute script**. [Руководство по Query Tool в pgAdmin](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool.html).

Скрипт создаёт две временные таблицы. Выполняйте все запросы в том же сеансе, в pgAdmin — в той же вкладке Query Tool. Если открыли новое соединение, снова запустите скрипт подготовки. [Временные таблицы в PostgreSQL](https://www.postgresql.org/docs/current/sql-createtable.html).

### Шаг 2. Познакомьтесь с выборкой

В таблице `practice08_rooms` одна строка соответствует аудитории. В таблице `practice08_requests` одна строка соответствует заявке. Поле `room_id` связывает заявку с аудиторией, из которой можно узнать площадку.

1. Запустите `SELECT COUNT(*) FROM practice08_requests;` и убедитесь, что в таблице 20 заявок.
2. Запустите `SELECT * FROM practice08_requests ORDER BY request_id LIMIT 5;` и посмотрите, как записаны даты и статусы.
3. Зафиксируйте период работы — 5 и 6 октября 2026 года. Все значения времени в наборе указаны в одном местном часовом поясе. Статус каждой заявки показан на момент снимка **6 октября 2026 года в 18:00**.

| Поле | Что означает |
| --- | --- |
| `room_id` | Идентификатор аудитории в обеих таблицах. |
| `campus`, `room_number` | Название площадки и номер аудитории в таблице аудиторий. |
| `request_id` | Идентификатор заявки. |
| `created_at` | Дата и время подачи заявки. |
| `status` | Состояние заявки на момент снимка. |
| `decided_at` | Дата и время решения администратора. Значение `NULL` означает, что решения администратора нет. |

Статусы в наборе — `PENDING` (на рассмотрении), `APPROVED` (подтверждена), `REJECTED` (отклонена) и `WITHDRAWN` (отозвана заявителем).

### Шаг 3. Определите час с наибольшим количеством заявок

**Вопрос 1. В какой час суток за два учебных дня поступило больше всего заявок?**

1. Используйте все статусы. Включите заявки с `2026-10-05 00:00:00` до `2026-10-07 00:00:00`. Начало периода включается, конец служит верхней границей и исключается.
2. Получите час из `created_at` через `EXTRACT(HOUR FROM created_at)`. Сгруппируйте по часу суток, чтобы, например, заявки с 09:00 до 09:59 за оба дня попали в одну строку.
3. Посчитайте строки в каждой группе через `COUNT(*)`. Отсортируйте по числу заявок от большего к меньшему. Сохраните весь результат с двумя колонками — **Час суток** и **Количество заявок**.
4. В выводе укажите самый загруженный интервал и число заявок за него. Например, час со значением `9` читается как интервал с 09:00 до 10:00. Если при анализе другой выборки несколько часов делят максимум, укажите все такие часы.

[Функции даты и времени в PostgreSQL](https://www.postgresql.org/docs/current/functions-datetime.html) · [Агрегирование в PostgreSQL](https://www.postgresql.org/docs/current/tutorial-agg.html).

### Шаг 4. Посчитайте заявки на рассмотрении по площадкам

**Вопрос 2. Сколько заявок, поданных в тот же период, остаётся на рассмотрении на момент снимка на каждой площадке?**

1. Начните с таблицы аудиторий. Присоедините заявки через `LEFT JOIN` по `room_id`. В результате должны остаться обе площадки, в том числе площадка, где подходящих заявок нет.
2. Ограничьте подходящие заявки периодом из шага 3 и статусом `PENDING`. Один из способов сохранить строки без подходящей заявки — поместить эти ограничения в условие `ON` при соединении.
3. Сгруппируйте строки по `campus` и посчитайте идентификаторы присоединённых заявок. В результате должны быть две колонки — **Площадка** и **Количество заявок на рассмотрении**.
4. Запишите короткий вывод. Укажите, на какую дату относятся остатки заявок, и объясните, на какой площадке стоит проверить очередь в первую очередь, если цель — разобрать ожидающие заявки.

[Соединения таблиц в PostgreSQL](https://www.postgresql.org/docs/current/queries-table-expressions.html#QUERIES-JOIN).

### Шаг 5. Проверьте результат и сохраните выводы

1. Сложите значения по часам из первого отчёта. Для этой выборки сумма должна совпасть с числом заявок, которое получили на шаге 2.
2. Проверьте, что во втором отчёте видны обе площадки. Сверьте сумму по площадкам с отдельным подсчётом заявок со статусом `PENDING` за тот же период.
3. Сохраните два SQL-запроса, две таблицы результатов и по одному короткому выводу к каждому вопросу. В выводах назовите период или момент снимка и используйте фактические числа из результатов.

## Подсказки по ключевым частям

- **Период.** Укажите нижнюю границу через `>=`, а верхнюю — через `<`. Так в период попадут все заявки за 5 и 6 октября, даже если они поданы поздно вечером.
- **Группировка.** `GROUP BY` собирает строки с одинаковым значением в группу. В первом отчёте это одинаковый час суток, во втором — одна и та же площадка.
- **Подсчёт после соединения.** `COUNT(*)` считает все строки группы, а `COUNT(request_id)` — только строки с заполненным идентификатором заявки. При `LEFT JOIN` это различие важно для площадок с нулевым результатом. [Агрегатные функции PostgreSQL](https://www.postgresql.org/docs/current/functions-aggregate.html).
- **Два разных показателя.** Число поданных заявок описывает поток обращений за период. Число заявок на рассмотрении описывает остаток на момент снимка. Сравнивайте их с учётом этого различия.

## Выгрузка для задания по Python

Чтобы продолжить анализ в следующем задании, выполните запрос в том же сеансе, пока временные таблицы доступны.

```sql
SELECT
    r.request_id,
    a.campus,
    a.room_number,
    r.created_at,
    r.status,
    r.decided_at
FROM practice08_requests AS r
JOIN practice08_rooms AS a ON a.room_id = r.room_id
ORDER BY r.request_id;
```
