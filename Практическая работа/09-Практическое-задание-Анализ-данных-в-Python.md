### Шаг 3. Рассчитайте время до решения

Для метрики возьмите только подтверждённые и отклонённые заявки (`APPROVED` и `REJECTED`), у которых известны площадка и обе даты. Для каждой такой заявки вычтите время подачи из времени решения и переведите разницу в минуты. В эту метрику входят календарные минуты между событиями.

```python
has_decision_status = df["status"].isin(["APPROVED", "REJECTED"])
decided = df.loc[has_decision_status].dropna(
    subset=["campus", "created_at", "decided_at"]
).copy()

print("Решений с пропущенными данными:", has_decision_status.sum() - len(decided))

decided["decision_minutes"] = (
    decided["decided_at"] - decided["created_at"]
).dt.total_seconds() / 60

negative = decided["decision_minutes"] < 0
print("Отрицательных длительностей:", negative.sum())
decided = decided.loc[~negative].copy()
print("Заявок в расчёте:", len(decided))
```

Запишите, сколько строк вошло в расчёт и почему остальные исключены. Если нашли отрицательную длительность, проверьте даты в исходной строке. [Перевод интервала в секунды в pandas](https://pandas.pydata.org/docs/reference/api/pandas.Series.dt.total_seconds.html).

### Шаг 4. Сравните площадки

Сгруппируйте заявки с решением по площадке. Для каждой группы посчитайте количество заявок в расчёте и медиану длительности через NumPy. Медиана показывает середину упорядоченного ряда. При чётном числе наблюдений берётся среднее двух центральных значений.

```python
report = (
    decided.groupby("campus", as_index=False)
    .agg(
        decisions=("decision_minutes", "size"),
        median_minutes=("decision_minutes", lambda values: np.median(values.to_numpy())),
    )
    .sort_values("campus")
)

print(report.to_string(index=False))
```

Сохраните таблицу с площадкой, количеством заявок и медианой в минутах. Для проверки одной группы отсортируйте её длительности и найдите медиану вручную. [Группировка в pandas](https://pandas.pydata.org/docs/user_guide/groupby.html#named-aggregation) · [Медиана в NumPy](https://numpy.org/doc/stable/reference/generated/numpy.median.html).

## Подсказки по ключевым частям

- **Пропуски.** Пустое время решения может соответствовать состоянию заявки. Сначала проверьте статус, затем решите, считать ли пропуск проблемой.
- **Единицы измерения.** Разница между двумя датами даёт длительность. В расчёте сначала получаются секунды, а деление на 60 переводит их в минуты.
- **Сравнение групп.** Указывайте число заявок рядом с медианой. Так видно, сколько наблюдений стоит за каждым значением.
- **Интерпретация.** График показывает различие в наблюдаемом времени. Для объяснения причины понадобятся дополнительные сведения, например время работы администраторов или состав заявок.
